# Architecture Decision Records

> 이 문서는 **하네스 가드레일**이다 (`/harness` 가 매 step 프롬프트에 주입한다).
> 아래 결정을 벗어나는 구현은 리뷰에서 되돌린다. 결정을 바꿀 땐 ADR 을 추가하고 이유를 남긴다.

## 철학

- **경계를 한곳에 모은다.** 인증·소유권 확인·외부 호출은 전부 api 를 통과한다.
  브라우저가 DB·Storage·Claude 에 직접 닿는 경로를 만들지 않는다
- **닫히는 쪽으로 기본값을 둔다.** 설정이 비어 있으면 열리는 게 아니라 막힌다
- **과도한 추상화 금지.** 요청된 범위만 구현하고, 범위를 넘는 리팩터링은 먼저 묻는다
- **조용히 틀리는 걸 가장 경계한다.** 프롬프트·소유권·입력 검증·파서는 깨져도 에러가 안 나므로 테스트로 묶는다

---

### ADR-001: pnpm 모노레포 + web/api 분리
**결정**: Next.js(web) 와 NestJS(api) 를 별도 앱으로 두고 pnpm workspace 로 묶는다. DB 접근은 `@ppp/db` 패키지로 공유한다.
**이유**: Claude API 키와 DB 자격증명을 브라우저가 닿지 않는 런타임에 격리해야 한다. 배포 단위도 다르다(Vercel / Render).
**트레이드오프**: Next 의 서버 액션·라우트 핸들러만으로 끝낼 수 있었던 것을 CORS·토큰 전달·두 번 배포로 치른다.

### ADR-002: 인증은 Supabase Auth, 구글 OAuth 단독
**결정**: 계정·세션·OAuth 왕복을 Supabase Auth 에 맡긴다. 이메일/비밀번호는 만들지 않는다.
**이유**: 직접 구현하면 비밀번호 저장·재설정·검증 메일까지 떠안는다. 취업 준비생은 구글 계정을 거의 다 갖고 있다.
**트레이드오프**: Supabase 에 종속된다. 구글 계정이 없는 사용자는 가입할 수 없다.
> Auth.js(next-auth) 는 2026-11-02 에 걷어냈다. 다시 끌어오지 말 것.

### ADR-003: JWT 를 JWKS 로 로컬 검증한다 (ES256)
**결정**: api 는 web 이 보낸 Supabase 액세스 토큰을 **JWKS 공개키로 로컬 검증**한다. 매 요청 Supabase 에 묻지 않는다.
**이유**: 이 프로젝트는 비대칭 키(ES256)라 시크릿 공유가 필요 없고, DB·네트워크 조회가 없어 빠르다.
**트레이드오프**: 토큰 만료 전까지는 강제 로그아웃이 즉시 반영되지 않는다. 필요해지면 별도 처리.

### ADR-004: RLS 를 쓰지 않는다 — 소유권은 api 쿼리로 확인한다
**결정**: Row Level Security 를 켜지 않고, 모든 조회/수정에 `userId` 조건을 걸어 본인 소유인지 확인한다.
**이유**: 브라우저가 DB 에 직접 붙지 않는다. 접근 경로가 api 하나뿐이라 정책을 두 곳(SQL·앱)에 둘 이유가 없다.
**트레이드오프**: api 코드에서 `userId` 조건을 빠뜨리면 그대로 유출된다 → 소유권 검사는 **테스트 필수 항목**이다.

### ADR-005: Prisma 7 — 스키마에 url 을 두지 않는다
**결정**: 런타임은 driver adapter(`DATABASE_URL`), 마이그레이션은 `prisma.config.ts`(`DIRECT_URL`) 로 분리한다. 생성물은 `packages/db/src/generated/prisma`.
**이유**: Prisma 7 은 스키마 안의 `url` 을 금지한다. 생성물이 `src/` 안에 있어야 tsc 빌드 결과(dist)에 포함된다.
**트레이드오프**: 스키마를 고치면 `pnpm db:migrate` 와 **`pnpm db:build` 를 같이** 돌려야 api 가 새 타입을 본다 — 잊으면 옛 타입으로 컴파일된다.

### ADR-006: 모델은 claude-opus-5, 샘플링 파라미터를 쓰지 않는다
**결정**: `@anthropic-ai/sdk` + `claude-opus-5`. `temperature`/`top_p`/`top_k` 를 넘기지 않는다. 같은 입력에 다른 결과가 필요하면 **프롬프트에서** 변화를 만든다(예: `interview-prompt.ts` 의 `OPENING_ANGLES`).
**이유**: Opus 5 는 이 파라미터를 받으면 400 으로 거절한다.
**트레이드오프**: 다양성 제어가 프롬프트 설계 문제로 넘어온다. 코드 한 줄로 조절할 수 없다.

### ADR-007: 긴 응답은 스트리밍하고 NDJSON 으로 중계한다
**결정**: 첨삭·면접 응답은 streaming 으로 받아 NDJSON 한 줄씩 브라우저로 보낸다. web 은 `use-stream-text` 로 조립한다.
**이유**: 첨삭 한 건이 수천 토큰이다. 다 받고 한 번에 주면 사용자가 수십 초 빈 화면을 본다.
**트레이드오프**: 중간에 끊긴 응답을 다룰 코드가 늘고, 토큰 수 기록이 스트림 종료 시점으로 밀린다.

### ADR-008: `max_tokens` 는 사고 + 응답 합계로 잡는다
**결정**: 사고(thinking)가 기본으로 켜져 있다는 전제로 `max_tokens` 를 넉넉히 둔다.
**이유**: 응답 길이만 보고 잡으면 사고가 예산을 먹고 답이 중간에 잘린다.
**트레이드오프**: 상한이 느슨해져 비용 예측이 어렵다 → `CostGuard` 로 따로 막는다.

### ADR-009: 레이트리밋(메모리)과 비용 가드(DB)를 분리한다
**결정**: `RateLimitGuard` 는 짧은 시간의 요청 폭주를 프로세스 메모리로, `CostGuard` 는 24시간 누적 토큰을 DB 집계로 막는다. 섞지 않는다.
**이유**: 막으려는 대상이 다르다. 폭주는 즉시·저비용으로 판단해야 하고, 누적 비용은 인스턴스와 무관해야 한다.
**트레이드오프**: 레이트리밋이 메모리라 **인스턴스를 늘리면 실효 한도가 곱해진다.** Render 단일 인스턴스 전제가 깨지면 Redis 로 옮겨야 한다.

### ADR-010: 요청 로그는 미들웨어로 수집한다 (인터셉터 아님)
**결정**: `RequestLogMiddleware` 를 `'{*path}'` 에 걸고 `res.on('finish')` 에서 기록한다.
**이유**: 인터셉터는 가드보다 뒤라서 **가드가 거절한 401·404 가 전부 누락된다** — 운영에서 가장 보고 싶은 게 거절된 호출이다. `finish` 시점이면 최종 상태코드와 가드가 채운 `request.user` 를 둘 다 읽을 수 있다.
**트레이드오프**: 단위 테스트로는 "Nest 가 미들웨어를 불러주는지"를 확인할 수 없다 → `test/request-log.e2e-spec.ts` 가 그 역할을 하고 CI 에서 돈다. 경로를 `'*path'` 로 쓰면 루트 `GET /` 가 빠진다(Express 5 문법).

### ADR-011: 요청 본문과 헤더는 기록하지 않는다
**결정**: 로그에 메서드·경로·상태코드·소요시간·사용자만 남긴다. 본문·헤더·쿼리스트링은 떼어낸다.
**이유**: 본문엔 이력서·자소서 전문이 들어 있고, 헤더엔 액세스 토큰이 들어 있다.
**트레이드오프**: 재현이 어려운 버그를 로그만으로 추적할 수 없다.

### ADR-012: 로그는 메모리 링 버퍼에 담는다
**결정**: `monitoring/log-buffer.ts` 의 고정 크기 링 버퍼에 최근 로그를 담고 관리자 화면에서 읽는다.
**이유**: 외부 수집 도구 없이 "지금 무슨 일이 일어나는지"를 보려면 이게 가장 적은 비용이다.
**트레이드오프**: 재시작하면 사라지고 인스턴스별로 따로 쌓인다. 장기 보관이 필요해지면 외부로 보내야 한다.

### ADR-013: 관리자는 `ADMIN_EMAILS` 로 가르고, 권한 없으면 404 를 던진다
**결정**: 관리자 판별은 api 전용 `.env` 의 `ADMIN_EMAILS`(쉼표 구분)다. **비우면 아무도 관리자가 아니다.** `AdminGuard` 는 403 이 아니라 **404** 를 던진다. 이메일은 Supabase 가 검증한 JWT 클레임에서 읽는다.
**이유**: 설정 실수로 전원 공개되는 쪽으로 열리지 않아야 한다. 403 은 "그 엔드포인트가 있고 너는 권한이 없다"를 알려주는 셈이라, 관리자 화면은 존재 자체를 숨긴다.
**트레이드오프**: 관리자 추가가 재배포 작업이 된다. `/me` 의 `admin` 필드는 **메뉴를 숨기는 편의용**일 뿐 실제 차단은 api 가 한다.

### ADR-014: 파일은 Supabase Storage 비공개 버킷, PDF 만
**결정**: 업로드는 브라우저 → api → Storage 경로다. 지원 형식은 PDF 뿐이고 추출은 `unpdf` 를 쓴다.
**이유**: 소유권 확인을 api 한곳에 모으기 위해 직접 업로드를 쓰지 않는다. `unpdf` 는 네이티브 의존성이 없어 Render 빌드가 단순하다.
**트레이드오프**: 큰 파일이 api 를 거쳐 메모리를 쓴다(본문 상한 1mb). DOCX 는 필요해지면 추가.

### ADR-015: 서버 상태는 TanStack Query, UI 와 데이터를 분리한다
**결정**: 서버 상태는 TanStack Query 로만 다룬다. `components/ui/` 는 props 만 받는 순수 UI 고, 페칭은 상위 데이터 컴포넌트가 한다. 쿼리 키는 `lib/query/keys.ts` 에만 둔다.
**이유**: 페칭이 UI 안에 섞이면 재사용이 끊기고, 키가 흩어지면 무효화가 어긋난다.
**트레이드오프**: 컴포넌트 수가 늘고 props 를 한 단계 더 내려야 한다.

### ADR-016: api 호출 함수는 `ApiError` 를 던진다
**결정**: 성공/실패 유니온을 반환하지 않고 예외를 던진다.
**이유**: Query 가 `error`/`isError` 로 다루게 하려면 던져야 한다.
**트레이드오프**: 호출부가 try/catch 를 의식해야 한다.

### ADR-017: Next 16 — `middleware.ts` 가 아니라 `proxy.ts`
**결정**: 미들웨어 파일은 `apps/web/src/proxy.ts` 이고 내보내는 함수도 `proxy`(또는 default) 다.
**이유**: Next 16 에서 이름이 바뀌었다. 블로그·튜토리얼을 그대로 복사하면 **파일이 호출되지 않아 세션이 갱신되지 않고 로그아웃된다.**
**트레이드오프**: 외부 예제와 이름이 달라 혼동된다. `setAll` 이 마지막으로 만든 응답 객체를 **그대로 반환**해야 쿠키가 실린다.

### ADR-018: 테스트는 외부를 호출하지 않는다
**결정**: 테스트 파일은 `*.spec.ts` 로 소스 옆에 둔다. Claude·Storage·DB 는 목으로 대체한다. 우선순위는 **프롬프트 내용 · 소유권 검사 · 입력 검증 · 파서**. 배선 확인은 e2e(`apps/api/test/*.e2e-spec.ts`) 로 따로 돌린다.
**이유**: 이 넷이 깨지면 에러 없이 조용히 잘못 동작하거나 보안 문제가 된다. 네트워크에 의존하는 테스트는 CI 를 불안정하게 만든다.
**트레이드오프**: 실제 Claude 응답 품질은 테스트가 보증하지 못한다 → 수동 확인으로 남는다. web 테스트는 node 환경의 **순수 로직만**이고, 컴포넌트 렌더링 테스트는 필요해질 때 jsdom 을 추가한다.

### ADR-019: 배포는 Vercel(web) + Render(api), 단일 인스턴스
**결정**: web 은 Vercel 의 `apps/web`, api 는 레포 루트 `render.yaml`. Render 는 Root Directory 를 비우고 빌드 명령에 **`pnpm db:build` 를 먼저** 둔다. 마이그레이션은 로컬에서 `pnpm db:deploy`.
**이유**: Render 는 루트 디렉터리 밖 파일을 제공하지 않아 모노레포는 루트에서 빌드해야 한다. 무료 플랜은 Pre-Deploy·셸이 없어 배포 중 마이그레이션을 돌릴 수 없다.
**트레이드오프**: 무료 플랜은 15분 유휴 후 스핀다운(재기동 ~1분)이다. 단일 인스턴스라서 메모리 레이트리밋·링 버퍼가 설계대로 동작하지만, **스케일업하는 순간 둘 다 깨진다.**
