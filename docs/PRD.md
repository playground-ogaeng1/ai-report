> 진행 상황은 여기가 아니라 [TODO.md](./TODO.md) 에 적는다.

## 목표

취업 준비생이 **자기 문서(이력서·자소서·포트폴리오)를 근거로** 첨삭을 받고 모의 면접을 볼 수 있게 한다.

## 사용자

취업·이직을 준비하는 개인. 구글 계정으로 로그인하는 단일 역할이다.
운영자용 조회 화면이 따로 있지만 별도 역할이 아니라 **이메일 화이트리스트**로 가른다.

## 핵심 기능

1. **문서 등록** — 이력서·자소서·포트폴리오를 텍스트 직접 입력 또는 PDF 업로드로 등록한다.
   PDF 는 등록 시점에 텍스트를 추출해 보관한다 (추출 실패 = 등록 실패).
2. **자소서 첨삭** — 등록한 문서에 대해 Claude 가 피드백을 생성한다. 응답이 길어 **스트리밍**한다.
3. **AI 모의 면접** — 등록 문서를 컨텍스트로 **텍스트 채팅** 면접을 진행한다.
   난이도(EASY·NORMAL·HARD)는 **꼬리질문 개수와 파고드는 깊이**로만 구분하고, 질문 주제 자체는 바꾸지 않는다.
   종료하면 총평을 남긴다.
4. **사용량 표시** — 24시간 누적 토큰 사용량을 사용자에게 보여준다.
5. **운영 조회** — 관리자만 최근 요청 로그·엔드포인트 통계·애플리케이션 로그를 본다.
6. **버그 신고** — 모든 화면 우하단 위젯에서 신고를 받아 메일로 보낸다.

## MVP 제외 사항

- **음성 면접** — 텍스트 채팅만. 음성 입출력은 없다
- **이메일/비밀번호 로그인** — 구글 OAuth 단독
- **자소서 초안 생성** — 첨삭(가진 글을 고치기)만 한다. 백지에서 써주는 기능은
  지원자가 쓰지 않은 사실이 들어갈 위험이 커서 프롬프트 설계가 달라진다. 별도 판단 사항
- **PDF 외 파일 형식** — DOCX 등은 필요해지면 추가
- **다중 사용자 협업·공유** — 문서는 본인만 본다
- **RLS(Row Level Security)** — 브라우저가 DB 에 직접 붙지 않으므로 필요한 구조가 아니다

## 디자인

- **도구처럼 보여야 한다.** 마케팅 랜딩이 아니라 매일 쓰는 작업 화면이다
- **라이트/다크 모드 둘 다** 지원한다 (OS 설정을 따른다). 한쪽 고정이 아니다
- 무채색 기반. 색은 **상태를 말할 때만** 쓴다 (성공·경고·에러·정보)
