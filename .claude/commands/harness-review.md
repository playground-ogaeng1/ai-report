이 프로젝트의 변경 사항을 **하네스 가드레일 기준으로** 리뷰할 것.

> 일반적인 버그 사냥은 `/code-review` 가 한다. 이 명령은 "가드레일을 벗어났는지"만 본다.

먼저 다음 문서들을 읽어라:

- `/CLAUDE.md`
- `/docs/ARCHITECTURE.md`
- `/docs/ADR.md`
- `/docs/UI_GUIDE.md` (web 변경이 있으면)

그런 다음 변경된 파일들을 확인하고(`git diff master...HEAD` 또는 워킹 트리), 아래 체크리스트로 검증하라:

## 체크리스트

1. **아키텍처 준수** — ARCHITECTURE.md 의 디렉토리 구조와 레이어 규칙을 따르는가?
   - `components/ui/` 에 `useQuery` 가 들어가지 않았는가?
   - 쿼리 키가 `lib/query/keys.ts` 밖에 흩어지지 않았는가?
   - api 호출 함수가 실패 시 `ApiError` 를 던지는가? (성공/실패 유니온 반환 금지)
2. **기술 스택 준수** — ADR 의 결정을 벗어나지 않았는가? 새 의존성이 추가됐다면 ADR 에 근거가 있는가?
3. **보안·소유권** — 모든 데이터 조회/수정이 본인 소유인지 확인하는가? 리소스 ID 만 믿고 반환하지 않는가?
4. **Claude 호출 규칙** — `temperature`/`top_p`/`top_k` 를 쓰지 않았는가? 키가 `apps/web` 으로 넘어가지 않았는가? 긴 응답에 streaming 을 쓰는가?
5. **가드 순서** — `RateLimitGuard`/`CostGuard` 가 `SupabaseAuthGuard` 뒤에 오는가? Claude 를 호출하는 엔드포인트에 `CostGuard` 가 붙었는가?
6. **테스트 존재** — 프롬프트 내용·소유권 검사·입력 검증·파서를 건드렸다면 테스트가 있는가? 파일명이 `*.spec.ts` 이고 소스 옆에 있는가?
7. **enum 네 곳** — 스키마 enum 을 추가했다면 schema.prisma → `db:build` → api 의 `Record<…>` → `apps/web/src/lib/api/index.ts` 를 모두 고쳤는가?
8. **검증 통과** — `pnpm lint`, `pnpm typecheck`, `pnpm test` 가 에러 없이 통과하는가? (직접 실행해서 확인하라)
